# 한국형 스타트업 IR 제작 — Claude용

사업자료를 이해한 뒤 한국 투자자·심사위원·고객이 판단할 수 있는 실제 발표자료를 완성하라. 이 스킬은 IR 논리, 근거, 장별 설계, 한국어 발표문과 품질 관리를 맡는다. Claude에 제공되는 PowerPoint 제작 기능은 실제 파일 작성에 활용하라. 특정 회사·산업·모델·목차·장수·폰트 설치 경로를 고정하지 마라.

## 1. 실행 범위와 읽을 자료

현재 사용자 요청과 실제 제출조건, 회사 원자료, 이 스킬의 기본값 순으로 적용하라. 상위 지침과 현재 권한을 지켜라. 이미 받은 자료와 대화를 읽고 같은 정보를 다시 묻지 마라.

| 작업 | 완료할 범위 |
|---|---|
| create | 요청한 실제 PPTX, 발표 노트와 필요한 검수 |
| revise | 원본을 보존한 수정본과 영향받은 내용·화면 검수 |
| review | 실제 자료를 읽은 검토 결과와 구체적인 수정안 |
| content-only | 요청한 이야기·목차·장별 문구·대본·근거 기록 |

단순 IR 개념 질문이나 한 장 수정에 전체 덱 제작 절차를 강제하지 마라. 전체 PPT 제작 요청은 구성안만 제시하고 끝내지 마라.

먼저 [Claude 실행 지침](references/claude-runtime.md)을 읽고 현재 파일·코드 실행 환경을 확인하라. 이후 단계별로 필요한 참조만 읽어라.

## 2. 자료를 읽고 발표 결정을 정하라

1. 첨부 파일의 본문·표·화면·발표 노트를 실제로 읽어라. 파일명만으로 내용을 안다고 판단하지 마라. 읽지 못한 HWP·스캔·수식·이미지 속 숫자는 확인 상태를 분리하라.
2. 투자유치, 데모데이, 지원사업, 제휴 중 목적을 파악하라. 현장 발표용인지 독립 열람용인지 별도로 정하라.
3. 청중, 회사 단계, 현재 제품 상태, 시간과 Q&A 포함 여부, 장수·비율·파일 규격, 지정 양식·평가표, 브랜드를 확인하라.
4. 이미 받은 정보로 가능한 작업을 진행하라. 사소한 디자인 선택마다 승인을 기다리지 마라. 중요한 사업 사실과 제출조건이 없으면 표시한 초안을 만든 뒤 질문을 모아라.
5. 외부 발송·신청·게시, 전역 설정 변경, 계정 연결은 별도의 실제 사용자 권한을 확인하라. PPT 제작 요청을 이러한 행동의 권한으로 확대하지 마라.

## 3. 사실·보고·계산·가정을 연결하라

전체 덱은 contracts.md의 ir-plan.json으로 주장·근거·요구사항·장표를 연결하라. 작은 수정은 영향받는 부분만 갱신하라.

- 주장을 fact / reported / derived / forecast / hypothesis / missing으로 구분하고 파일·시트·페이지·URL·기준일·단위·모수를 연결하라.
- 회사가 제공한 사실을 자연스럽게 발표하되, 별도 증빙을 보지 않았다면 내부 원장에 그 범위를 남겨라. 출처를 열람했다고 허위 기록하지 마라.
- 무료시험·의향·협약·PoC·계약·입금·반복 사용을 구분하라. 과거 메신저 시험을 현재 앱의 유료 사용 실적으로 바꾸지 마라.
- 계약액·매출·거래액·입금, 월·연·누적, 원·만원·백만원·억원, 실적·전망을 구별하라. 금액이 다르면 정의·기간·포함 범위부터 대조하라.
- 현재 공고·가격·경쟁 기능·통계는 사용 가능한 조사 도구로 공식 원문을 확인하라. 사용자가 조사를 제외했거나 접근할 수 없으면 확인하지 않은 상태를 보존하라.
- SOM은 판매 경로·도달 가능한 고객·전환 가정·공급 역량에 연결하라. 근거가 부족한 전체 사업체 수에 가정 가격을 곱한 값을 확보 가능한 시장으로 제시하지 마라.
- 지원사업은 실제 평가표와 장표를 대응하라. 공개되지 않은 배점·합격선·사업비 규정은 만들지 마라.

## 4. 청중 질문에서 이야기와 HOW를 설계하라

1. 청중이 내려야 할 결정과 그 결정에 필요한 근거를 정하라. 사업 단계와 자료량, 발표시간에 맞춰 순서를 구성하라.
2. 장별로 청중 질문, 기억할 결론 하나, 근거, 시각 표현, 발표 설명, 다음 장 연결을 정하라. 제목만 읽어도 이야기가 이어지는지 확인하라.
3. 후킹은 고객 장면, 확인된 발견, 수치, 제품 동작, 의미 있는 대비에서 고르라. 근거보다 강한 제목을 쓰지 마라.
4. 제품은 실제 입력 → 사용자 조작 → 처리 → 출력 → 검토·수정·재사용을 필요한 범위까지 보여라. 추상적인 기능명을 상자에 나열하는 데서 끝내지 마라.
5. 실제 화면, 프로토타입, 설명용 예시와 계획을 구별하라. 아직 없는 기능이나 생성 이미지를 실제 사용 증거로 제시하지 마라.
6. 고객의 현재 대안을 포함해 경쟁을 설명하고, 미확인 경쟁 기능을 없다고 단정하지 마라. 차별성을 구매 이유와 증거에 연결하라.
7. 지불자·과금 단위·가격·제공 비용을 연결하라. 함께 작동하는 구독과 사용량 과금을 임의로 하나로 줄이지 마라.
8. 실제 팀원과 역량을 쓰고, 마지막 요청을 투자·지원 선정·제휴·파일럿 참여 등 목적에 맞추라. 가격·투자금이 미정이면 지어내지 마라.

## 5. 실제 PPTX와 한글 화면을 제작하라

create/revise에서만 실제 파일 제작을 수행하라. 현재 환경의 PowerPoint/PPTX 제작 기능이 제공되면 그 실제 지침을 읽고 사용하라. 사용 가능한 기능을 확인하지 못했으면 claude-runtime.md의 대체 경로를 따르라.

- 브랜드·템플릿이 있으면 실제 파일을 읽고 적용하라. 없으면 내용과 청중에 맞는 방향을 정해 진행하라.
- 글꼴·색·여백·표기는 통일하고, 비교·제품 흐름·증거·일정에 맞는 구도를 선택하라. 모든 장을 같은 카드나 두 열 배치로 만들지 마라.
- 텍스트·표·일반 차트는 편집 가능한 객체를 우선하라. 실제 화면 등 필요한 요소만 이미지로 넣고 편집 제한을 밝혀라.
- 정확한 도식과 수치 차트는 편집 도구·코드로 그려라. 생성 이미지에 정확한 데이터 표현을 맡기지 마라.
- 실제 사용 가능한 한글 폰트를 확인하라. 이름 지정, 설치 여부, 렌더에 사용된 글꼴을 구분하라. 한글 깨짐·줄바꿈·숫자와 단위·각주의 가독성을 확인하라.
- 텍스트가 넘치면 문장과 구도를 먼저 조정하라. 글자를 작게 줄여 정보량을 감추지 마라.
- 기존 PPT는 원본을 보존하고 수정본의 차트·이미지·마스터·노트 손실을 확인하라.

## 6. 한국어 발표문과 시간 버전을 작성하라

- 주요 설명은 PREP의 결론 → 이유 → 근거·동작 → 의미·다음 연결을 자연스럽게 사용하라. 표지·전환·마무리에 네 단계를 기계적으로 반복하지 마라.
- 회사 발표자의 관점으로 말하라. 내부 검수 과정이나 제외한 수치를 대본에서 반복하지 마라. 해석에 중요한 무료/유료·기간·미측정 상태는 가까운 짧은 표현으로 보존하라.
- 발표 노트에는 발화, 짚을 화면, 강조·멈춤과 다음 연결을 넣어라. 도구가 지원하면 PPTX 노트에도 넣고 대본과 일치시켜라.
- 요청한 시간 버전만 만들라. 5분은 300초, 7분은 420초 안에 발화·전환·데모·여유를 배분하라. 실제 행사 조건이 우선이다.
- 실제 낭독 없이 발표시간을 실측했다고 말하지 마라. 여러 버전의 수치·회사 정의·제품 상태를 일치시켜라.
- 큐카드와 예상 질문은 요청 범위에 맞춰 제공하라. Q&A 제외 요청을 지켜라.

## 7. 내용과 실제 파일을 검수하라

자동 검사와 의미·시각 검수를 구분하라. 두 검사 스크립트는 Python 표준 라이브러리로 실행한다. IR_SKILL_DIR는 현재 읽은 이 SKILL.md가 있는 실제 폴더, IR_PROJECT_DIR는 확인한 작업 폴더로 지정한 로컬 변수다. 설치 폴더에 산출물을 쓰지 마라.

```bash
python3 "$IR_SKILL_DIR/scripts/pptx_audit.py" --preflight
python3 "$IR_SKILL_DIR/scripts/ir_audit.py" --plan "$IR_PROJECT_DIR/ir-plan.json" --out "$IR_PROJECT_DIR/plan-audit.json"
python3 "$IR_SKILL_DIR/scripts/pptx_audit.py" "$IR_PROJECT_DIR/ir.pptx" --out "$IR_PROJECT_DIR/pptx-audit.json"
```

1. 원자료와 주장·수치·단위·조건·필수 항목을 대조하라. 자동 검사 결과가 사실성을 보증하지는 않는다.
2. 실제 최종 PPTX를 사용 가능한 렌더러로 PDF/이미지로 변환하고 전체 흐름과 모든 장을 직접 확인하라. 별도 HTML 시안으로 PPTX 검수를 대신하지 마라.
3. 잘림·겹침·한글·차트·각주·읽기 위계를 고치고 영향받은 장을 다시 렌더하라.
4. 실제 독립 검토 기능이 있으면 원자료·요구·최종 덱을 전달하라. 없으면 직접 투자자와 심사위원 관점으로 검토하고 독립 검토를 했다고 말하지 마라.
5. 최신 원장·PPTX·실제로 본 렌더의 해시를 review.json에 연결하라. 보지 않은 이미지를 reviewed:true로, 미실시 검수를 pass로 채우지 마라.
6. 전체 제작과 검수가 완료됐을 때만 다음 검사로 완료 기록을 확인하라.

```bash
python3 "$IR_SKILL_DIR/scripts/ir_audit.py" --plan "$IR_PROJECT_DIR/ir-plan.json" --pptx "$IR_PROJECT_DIR/ir.pptx" --review "$IR_PROJECT_DIR/review.json" --release --out "$IR_PROJECT_DIR/release-audit.json"
```

중대한 오류는 가능한 범위에서 수정하라. 해결되지 않은 근거·렌더 문제는 초안과 남은 확인사항으로 정확히 전달하라. 검사 실패를 무조건 승인 대기나 무한 재작업으로 바꾸지 마라. 충분히 검증되면 전달하라.

## 8. Claude에서 파일을 전달하라

요청한 실제 PPTX, 가능한 PDF, 발표 노트·큐카드·Q&A를 현재 Claude 환경의 파일 출력 기능으로 전달하라. 다운로드 대상 파일의 존재를 확인하라. 스킬 폴더·내부 경로만 답하고 끝내지 마라.

제작 소스와 근거 원장은 후속 수정에 사용할 수 있게 작업 폴더에 보존하라. 최종 응답에는 목적·시간·장수, 중요한 구성 결정, 실제 수행한 검사와 남은 확인을 짧게 설명하라. 실제 리허설·PowerPoint 실행·투자자 평가를 하지 않았다면 완료했다고 주장하지 마라.

## 요청 예시

- “korean-startup-ir 스킬로 첨부한 사업자료를 분석해서 국내 VC 대상 7분 PPTX와 PREP 대본을 만들어줘.”
- “이 공고와 평가표에 맞춰 5분 지원사업 발표를 만들어줘. Q&A는 빼고 사업비와 실증계획을 연결해줘.”
- “이 IR의 제품 설명 3장만 개선해줘. 기존 브랜드와 실제 수치는 유지해줘.”
