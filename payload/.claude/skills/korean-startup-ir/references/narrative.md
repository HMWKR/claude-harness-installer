## 1. 청중이 내려야 할 판단부터 정하라

- 기존 자료에서 발표 목적, 청중, 사업 단계, 발표시간, 질의응답시간, 필수 목차, 요청 산출물을 추출하라. 이미 확인한 내용을 다시 질문하지 마라.
- 회사 이름이나 분야가 이전 작업과 같아도 최신 사업 정의와 제품 상태를 확인하라. 피벗 전 자료를 현재 실적으로 합치지 마라.
- VC·AC 발표는 고객의 구매 이유, 사업 확장 가능성, 회사의 실행 근거, 이번 자금이 달성할 변화에 맞춰라.
- 데모데이는 이해하기 쉬운 고객 상황, 실제 제품 경험, 기억할 근거, 행사 목적에 맞는 다음 행동에 집중하라.
- 정부·공공 지원 발표는 실제 공고·평가표·지정 양식을 우선하라. 필수 항목이 어느 슬라이드에서 입증되는지 대조하라. PSST를 모든 국내 사업의 공통 양식으로 가정하지 마라.
- 두 목적을 함께 요청받으면 같은 사실 자료에서 목적별 본문을 구성하라. 투자 검토와 지원사업 심사의 항목을 한 덱에 무조건 합치지 마라.
- 사용자가 정한 장수·시간·브랜드·표현 조건을 따르라. 조건이 없으면 필요한 판단과 설명 시간으로 장수를 결정하라. 고정된 장수나 슬라이드 순서를 품질 기준으로 삼지 마라.

## 2. 현재 단계에 맞는 가장 강한 검증 신호를 골라라

| 실제 상태 | 우선 살필 근거 | 구별할 상태 |
|---|---|---|
| 문제 탐색·출시 전 | 고객 관찰, 인터뷰, 현재 대안, 프로토타입 반응 | 관심·지불의사·결제 |
| 파일럿·초기 사용 | 테스트 범위, 작업 완료, 재사용, 피드백, 유료 여부 | 무료 시험·유료 실증·상용 도입 |
| 초기 유료 사업 | 실제 매출, 재구매·갱신, 활성 사용, 획득 경로, 제공 비용 | 등록·활성·유료 고객; 계약·수금·매출 |
| 성장·확장 | 코호트, 유지·이탈, 반복 매출, 채널별 성과, 영업기간, 수익성 | 일회성 성과·반복 가능한 성과 |
| 기술 실증·설비 사업 | 시험 조건, 재현성, 실증 범위, 인증·양산 진행 | 실험실·현장·상업 규모; 출원·등록 |

- 라운드 명칭만으로 증거를 요구하지 말고 실제 사업 상태와 업종을 함께 보라.
- 청중의 결정에 가장 관련 있는 확인된 근거를 앞쪽에 배치하라. 회사가 무엇을 하는지 모른 채 숫자만 보게 하지 마라.
- 약한 실적을 다른 지표로 부풀리지 마라. 해석에 중요한 실패·한계를 감추지 말고 현재 상태와 다음 검증으로 설명하라.
- 실적이 없으면 고객 문제의 근거, 접근법, 실행 결과, 검증 계획으로 구성하라. 표지의 숫자 슬롯을 채우기 위해 수치를 만들지 마라.
- 모델 호출, 자체 모델 개발, 미세조정, 업무흐름 설계를 구분하라. 외부 모델의 성능을 회사의 독자 성능으로 제시하지 마라.

## 3. 자료 목록을 설득의 순서로 바꿔라

- 핵심 청중 질문을 적고 각 질문에 답할 주장과 근거를 연결하라. 순서는 회사의 강점과 청중의 선행 이해에 맞춰 조정하라.
- 문제는 누가, 어떤 상황에서, 무엇을 시도하다, 어떤 손실을 겪는지로 설명하라. 손실 수치가 없으면 확인된 상황으로 표현하라.
- 해결책은 앞에서 제시한 문제와 연결하라. 제품 기능이 많다는 이유로 서로 다른 고객 문제를 한 이야기로 묶지 마라.
- 시장의 첫 고객, 실제 구매자, 사용자를 구별하라. 시장규모·가격·고객확보 계획이 같은 고객 집단을 가리키는지 확인하라.
- 시장 수치는 의미와 계산 근거가 있을 때 사용하라. 매 장에 수치, 유명 고객, 비교기업, 팀원, 외부 시장자료를 강제로 넣지 마라.
- 경쟁 구도에는 고객의 실제 대안도 포함하라. 미확인 기능을 없는 기능으로 표기하거나 편의적으로 유리한 비교축을 만들지 마라.
- 팀은 현재 인원과 역할을 반영하라. 관련 실행 경험과 부족한 역량의 보완 계획을 보여주고 가짜 공동창업자·고문을 추가하지 마라.
- 시기적 변화가 회사에 미친 영향을 입증할 수 있으면 설명하라. 유행 키워드만으로 별도의 Why Now 장을 만들지 마라.

## 4. HOW를 화면과 행동으로 설명하라

- 제품 설명에 `실제 입력 → 사용자 작업 → 제품 처리 → 출력 → 고객 가치`가 드러나게 하라. 필요하면 검토·수정·재사용을 이어라.
- 각 단계에서 사용자가 누르는 곳, 시스템이 처리하는 일, 받는 결과를 구분하라. 추상적인 기능 명칭을 다섯 상자에 넣는 것으로 끝내지 마라.
- 동작하는 제품은 실제 화면·실행 결과·짧은 데모로 보여라. 화면 전체가 읽히지 않으면 설명할 부분을 확대하고 맥락을 남겨라.
- 프로토타입·컨셉 화면·향후 기능은 상태를 명시하라. 생성 이미지를 실제 제품 화면이나 고객 성과로 제시하지 마라.
- 기술 신뢰가 핵심이면 고객 가치와 이어지는 처리 구조·시험 결과를 보여라. 상세 구조는 설명에 필요한 범위만 본문에 남겨라.
- 기존 방식과 비교할 때 같은 과업과 결과 조건을 사용하라. 측정하지 않은 절감률 대신 확인 가능한 단계·반복 입력·검토 방식의 차이를 보여라.
- 라이브 데모가 있으면 실패 시 설명할 정지 화면이나 결과물을 준비하라. 데모 재생·조작 시간을 발표 예산에 포함하라.

## 5. 각 장의 주장과 후킹을 설계하라

- 슬라이드마다 청중 질문, 기억할 주장 하나, 연결 근거, 핵심 시각자료, 발표 설명, 다음 장 연결을 정하라.
- 제목은 가능한 한 청중이 이해해야 할 결론을 전달하게 하라. 지정 목차명이 필요하면 별도 작은 표제로 보존하라.
- 한 주장에 여러 근거를 묶을 수 있다. 다른 결론을 설명하기 시작하면 분리하거나 부록으로 옮겨라.
- 후킹은 고객 장면, 검증된 발견, 의미 있는 수치, 전후 대비, 제품 동작, 판단을 여는 질문 중 내용에 맞는 방식으로 만들라.
- 수치가 없으면 수치 후킹을 생략하라. 강한 표현으로 증거의 범위를 넓히지 마라. 질문으로 시작했다면 해당 장이나 바로 다음 장에서 답하라.
- 모든 장에 같은 질문형 제목·카드·비교표를 반복하지 마라. 시각자료가 주장과 증거의 관계를 설명하게 하라.
- 제목만 순서대로 읽어도 회사·고객·제품·증거·사업성·다음 목표가 이어지는지 확인하라. 이 검사는 필수 목차를 제거할 이유가 아니다.

## 6. 발표용과 읽기용의 설명량을 조정하라

- 짧은 발표용은 발표자의 설명과 화면이 역할을 나누게 하라. 화면에는 핵심 주장과 읽을 수 있는 증거를 남기고 설명·전환은 노트에 넣어라.
- 읽기용은 발표자 없이 이해할 수 있도록 맥락, 지표 정의, 근거, 제한조건을 보강하라. 작은 글씨로 본문을 압축하지 마라.
- 읽기용을 추가 요청받지 않았다면 자동으로 별도 덱을 만들지 마라. 요청한 산출물부터 완성하라.
- 기술·재무·검증 세부자료는 필요에 따라 부록으로 분리하라. 발표 본문과 부록 장수·시간을 혼동하지 마라.
- 두 버전을 만들 때 표현량은 바꿔도 회사 정의, 제품 상태, 수치, 목표와 요청의 의미는 유지하라.
- 검수 원장의 상세 한계를 화면과 대본에 그대로 복사하지 마라. 해석에 중요한 무료/유료, 실적/목표, 기간과 표본은 가까운 짧은 라벨로 보존하고, 추가 확인 과제는 작업 메모·노트·부록에 정리하라. 필수 항목의 미확인을 숨기지는 마라.
- 검증할 자료가 없다는 설명을 모든 장의 주제로 만들지 마라. 이미 확인한 고객 상황·제품 동작·실행 결과와 다음 결정을 중심으로 설명하라. 제외한 수치나 내부 검토 과정을 굳이 발표문에서 나열하지 마라.

## 7. PREP를 자연스러운 노트와 큐카드로 작성하라

- 주요 설명 장은 기본적으로 PREP의 `결론 → 이유 → 근거·사례 → 의미·다음 연결`로 구성하되, 사용자가 다른 형식을 지정하면 그 형식을 우선하라. PREP라는 표제를 읽게 하지 마라.
- 표지·전환·마무리에 네 단계를 기계적으로 반복하지 마라. 같은 결론을 불필요하게 두 번 읽지 않도록 마지막 문장은 의미나 연결을 더하라.
- 화면의 문장을 그대로 읽는 원고를 피하라. 제품 장에서는 화면에서 무엇을 보거나 짚어야 하는지 설명하라.
- 회사 발표자의 관점에서 자연스럽게 말하라. `사용자가 제공한 자료에는` 같은 검수자 표현을 원고에 반복하지 마라. 회사 보고의 출처 상태는 내부 원장에 보존하고, 청중에게 필요한 조건과 한계는 핵심 주장 가까이에서 간결하게 설명하라.
- 발표 노트에 발화문, 강조할 부분, 가리킬 시각자료, 멈출 지점, 다음 장 연결을 기록하라.
- 큐카드를 요청받으면 같은 사실을 유지한 채 핵심어·근거·전환 문장으로 줄여라. 원고를 외우지 않아도 설명을 이어갈 수 있게 하라.
- 5분·7분을 모두 요청받으면 핵심 이야기는 공유하고 긴 버전에 데모 해설·검증 의미·실행계획을 보강하라. 긴 원고를 일정 비율로 잘라 짧은 원고로 만들지 마라.

## 8. 실제 발표시간을 배분하고 확인하라

- 발표시간과 Q&A 시간을 분리하라. 5분은 300초, 7분은 420초를 총예산으로 삼되 실제 행사 제한이 우선이다.
- 장별 발화, 화면 전환, 제품 조작, 영상, 청중 반응을 기다리는 시간을 합산하라. 핵심 설명에 필요한 여유를 남겨라.
- 장수로 시간을 균등 분할하지 마라. HOW·핵심 검증은 필요한 시간을 주고 표지·전환은 짧게 배정하라.
- 한국어 발표시간을 영어 단어 수 기준으로 확정하지 마라. 사용자 발화 속도나 실제 낭독이 없으면 추정이라고 표시하라.
- 리허설을 할 수 있으면 전체 시간과 밀리는 구간을 기록하고, 문장·장수·데모 길이를 조정하라. 하지 않은 리허설을 완료했다고 쓰지 마라.
- 시간을 줄일 때 핵심 근거와 중요한 한계는 보존하라. 추가 사례·중복 설명부터 줄이고 세부자료를 부록으로 옮겨라.

## 9. 자금·마일스톤·질문 대응을 연결하라

- 투자 요청은 금액·사용처·달성할 상태·시점을 연결하라. 운영 가능 개월 수만 제시하지 말고 그 기간에 무엇을 확인하는지 설명하라.
- 금액이나 가격이 미정이면 임의로 채우지 마라. 결정에 필요한 입력과 이미 정한 목표를 남겨라. 투자 모집이 목적이 아니면 투자 요청 장을 강제하지 마라.
- 매출 전망은 고객수·가격·전환·유지·비용 같은 입력과 연결하고 목표·가정을 실적과 구별하라.
- 구독과 사용량처럼 함께 작동하는 수익원은 실제 흐름으로 설명하라. 복수 매출원이라는 이유만으로 하나를 삭제하지 마라.
- 기술 사업은 이미 확인한 성능과 남은 검증을 구별하고 자금을 줄이려는 위험·실증 단계와 연결하라. 특정 자금조합이나 투자자 선호를 보편 규칙으로 강제하지 마라.
- Q&A가 필요하면 구매 이유, 대안, 검증, 시장 계산, 비용, 팀, 실행 제약, 자금 목표를 기준으로 질문을 고르라. 고정 개수를 채우려고 무관한 질문을 만들지 마라.
- 답변은 직접 답, 근거, 아직 모르는 부분, 확인 계획으로 구성하라. 본문보다 강한 실적을 Q&A에서 새로 만들지 마라.
- 사용자가 Q&A를 제외하면 생성하지 마라. 준비한 질문 목록을 투자 유치 성공 확률이나 심사 통과 보장으로 표현하지 마라.

## 10. 기존 자료 수정과 최종 일관성을 확인하라

- 먼저 현재 PPT의 장별 역할, 노트, 출처, 제품 상태, 브랜드, 사용자가 보존하라고 한 요소를 확인하라.
- 요청한 범위에 맞춰 수정하라. 일부 문구·숫자 변경을 전체 리디자인으로 확대하지 마라. 재구성이 요청되면 보존 조건을 지키며 구조를 바꿔라.
- 원본을 보존하고 수정본을 구별하라. 변경한 주장과 숫자가 등장하는 본문·차트·노트·부록·시간별 대본을 함께 갱신하라.
- 최신 자료가 이전 자료와 충돌하면 정의·기간·출처를 비교하라. 해결되지 않은 숫자를 골라 확정하지 말고 제외하거나 불확실성을 표시하라.
- 최종본에서 예시 실적, 가짜 고객, 미치환 자리표시자가 실제 사실처럼 남지 않았는지 확인하라. 미결정 사항이 중요한 초안은 완성본으로 부르지 마라.
- PPT·대본·큐카드·Q&A를 함께 확인하고 청중 질문, 근거, 제품 경험, 실행 목표가 끊기지 않게 수정하라.
