# PPTX 제작과 화면 검수

명령의 `IR_SKILL_DIR`와 `IR_PROJECT_DIR`는 [claude-runtime.md](claude-runtime.md)에 따라 실제로 확인한 스킬 폴더와 작업 폴더의 절대 경로로 먼저 설정한다. 기본 제공 환경변수라고 가정하지 않는다.

이 문서는 제작 단계에서 읽는다. 내용을 먼저 확정하고, 해당 프로젝트의 자료와 발표 목적에 맞춰 장별 화면을 설계한다. 고정된 장수·팔레트·레이아웃을 모든 프로젝트에 적용하지 않는다.

## 1. 제작 방식 선택

1. 현재 Claude 환경에 PowerPoint/PPTX 제작 기능이나 전용 스킬이 **실제로 제공되면** 발견한 실제 경로의 지침과 도구를 먼저 확인한다. 존재하지 않는 스킬·API를 가정하지 않는다.
2. 사용자가 지정한 PowerPoint·Google Slides 등 편집 환경이나 연결 도구가 있으면 입력·출력·편집 가능 범위를 확인한다.
3. 로컬에서 신규 PPTX를 만들 때 PptxGenJS가 사용 가능하면 활용한다. Python만 사용 가능한 경우 python-pptx로 작성할 수 있다.
4. 기존 파일 수정은 그 파일을 읽고 수정할 수 있는 도구를 사용한다. 신규 생성 라이브러리에 기존 PPTX 가져오기·완전 보존 기능이 있다고 가정하지 않는다.
5. `python3 "$IR_SKILL_DIR/scripts/pptx_audit.py" --preflight`는 로컬 명령과 라이브러리 가용성만 확인한다. 연결 도구와 플랫폼 전용 스킬은 별도로 확인한다.

도구가 없으면 이미 사용 가능한 대안을 선택한다. 모든 제작 경로가 없으면 검증된 내용·장별 설계·발표 대본까지 완성하고, PPTX 미생성 상태와 필요한 다음 단계를 정확히 보고한다. HTML/PDF를 만들었다면 해당 형식으로 설명한다.

## 2. 입력과 원본 보존

- 공고·제출 지침의 화면 비율, 장수, 파일 형식, 용량, 파일명, 동영상 허용 여부를 먼저 적용한다. 지정이 없을 때만 16:9를 시작점으로 삼는다.
- 원본 PPTX·템플릿·로고·사진을 덮어쓰지 않는다. 작업본과 결과본을 구분한다.
- 기존 덱을 수정할 때 화면 크기, 실제 슬라이드 순서, 마스터·레이아웃·테마, 노트, 표·차트·이미지를 먼저 조사한다.
- 사용자 지정 템플릿은 색·폰트·로고·여백을 실제 파일에서 확인한다. 변경할 부분과 보존할 부분을 기록한다.
- 템플릿 슬롯 수와 실제 자료 수가 다르면 슬롯을 조정한다. 빈 팀원·고객·매출을 만들어 채우지 않는다.
- 사용자가 PowerPoint에서 직접 수정한 내용이 있으면 재생성 전에 최신 파일과 제작 자료를 대조한다.

## 3. 내용에 맞는 화면 설계

덱 전체에서 글꼴 체계, 색의 역할, 여백, 표기법을 유지한다. 각 장은 `핵심 주장 → 필요한 증거 → 알맞은 시각 표현` 순서로 설계한다.

| 전달할 내용 | 가능한 표현 |
|---|---|
| 고객의 실제 불편 | 구체적인 상황, 현재 작업 흐름, 증거가 있는 전후 비교 |
| 제품의 작동 방식(HOW) | 실제 화면, 입력·처리·결과의 단계, 사용자 행동과 결과의 연결 |
| 검증 결과 | 조건·기간·분모가 명시된 표나 차트 |
| 경쟁 차이 | 같은 기준으로 비교한 항목과 근거 |
| 시장 진입 | 첫 고객군, 도달 경로, 구매 과정 |
| 자금과 다음 목표 | 사용 항목, 일정, 확인 가능한 달성 기준 |

- HOW 설명의 연결선·단계·주석은 가능한 한 편집 가능한 도형과 텍스트로 만든다.
- 스크린샷은 실제 제품 자료를 사용한다. 설명용 목업은 목업이라고 표시한다. 생성 이미지로 실제 제품·실적·고객을 위장하지 않는다.
- 데이터 없는 장에 장식용 차트를 넣지 않는다. 문장 하나가 효과적인 장에는 시각 요소를 억지로 추가하지 않는다.
- 같은 카드 구조를 연속 적용하기 전에 내용상 필요한지 판단한다. 반대로 다양성을 위해 의미 없는 레이아웃 변경을 하지 않는다.
- 근거 없는 최상급·반복 슬로건·본문을 되풀이하는 제목을 고친다. 강조는 검증된 주장과 핵심 행동에 사용한다.

## 4. 한글 글꼴과 가독성

1. 사용자 지정 글꼴을 우선한다. 지정이 없으면 제작 환경과 발표 환경에서 사용 가능한 한글 글꼴을 확인해 선택한다.
2. Pretendard, Noto Sans KR/CJK KR, Malgun Gothic 등은 후보이지 설치 보장이 아니다. 글꼴 이름을 파일에 지정한 것과 실제 렌더에 사용된 것을 구분한다.
3. `fc-match`가 성공했다고 요청 글꼴이 설치되었다고 판단하지 않는다. 실제 family와 대체 결과를 대조한다. 확인 도구가 없으면 `미확인`으로 기록한다.
4. 한글·영문·숫자·원화 기호 등 실제 문자열을 렌더링해 확인한다. 폰트 파일이 있다는 사실만으로 필요한 글리프 전체를 보증하지 않는다.
5. 지원되는 제작 API에서 한국어 언어 설정과 제목·본문 글꼴을 명시한다. PptxGenJS의 텍스트에는 `lang: "ko-KR"`을 사용할 수 있다.

현장 발표 본문은 22–28pt 수준을 시작점으로 삼고 실제 화면에서 조정한다. 이는 강제 규격이 아니다. 읽기용 제출본은 정보 밀도를 따로 설계한다. 내용이 넘치면 먼저 문장을 줄이거나 장을 나누고, 마지막 수단으로 글자 크기를 조정한다.

제목의 불필요한 줄바꿈, 한 글자만 남는 마지막 줄, 숫자와 단위의 분리, 표 셀의 잘림, 한글·영문 혼용 시 기준선 차이를 확인한다. 출처는 장에 짧게 표시하고 전체 URL·집계조건은 노트나 부록에 보관한다.

## 5. 데이터와 편집 가능한 객체

- 텍스트는 텍스트 객체, 표는 표 객체, 지원되는 일반 차트는 native chart로 만든다. 이미지·복잡한 시각화의 편집 제한은 별도 기록한다.
- 차트는 근거 자료의 값·단위·기간·지역을 그대로 반영한다. 누락값을 0으로 채우거나 예상치를 실적으로 표시하지 않는다.
- 실적과 전망을 구분하고, 서로 다른 기간·분모·통화를 비교할 때 변환 기준을 밝힌다. 수치·축·범례·주석을 원본 데이터와 대조한다.
- 정확한 수치 차트와 구조도는 생성 이미지로 만들지 않는다. 코드·native chart·벡터로 표현하고 원본 데이터를 보존한다.
- 사용자가 이미지형 PPT를 지정하면 따를 수 있다. 전체 장을 이미지로 넣은 결과를 완전 편집 가능한 PPTX로 설명하지 않는다.
- 사용한 로고·인물·사진·아이콘·폰트는 출처와 이용 조건을 확인한다. 실제 고객·파트너 로고와 증언은 제공되었거나 확인된 자료만 사용한다.
- 색만으로 실적/예상·좋음/나쁨을 구분하지 않는다. 라벨·선 종류·기호를 병행하고, 읽기 순서와 대체 텍스트를 지원 범위에서 정리한다.

## 6. 검수 순서

1. **근거·수치:** 내용 원장과 대조해 주장, 출처, 계산, 단위, 실적/가정 표시를 확인한다.
2. **자동 구조 검사:** `python3 "$IR_SKILL_DIR/scripts/pptx_audit.py" "$IR_PROJECT_DIR/ir.pptx" --out "$IR_PROJECT_DIR/pptx-audit.json"`을 실행하고 오류를 수정한다.
3. **렌더링:** 실제 PPTX를 사용 가능한 PowerPoint·LibreOffice 또는 플랫폼 렌더 도구로 PDF/PNG로 변환한다. 별도로 그린 HTML 시안을 PPTX 렌더 증거로 대신하지 않는다.
4. **화면 확인:** 전체 슬라이드 미리보기로 일관성과 흐름을 보고, 각 장의 이미지를 확대해 잘림·겹침·폰트·차트·주석·출처를 확인한다.
5. **수정:** 발견한 실제 결함을 제작 소스에서 수정하고 영향받은 장을 다시 렌더링한다. 결함이 해결되면 불필요한 반복을 멈춘다.
6. **발표 확인:** 배정 시간과 대본을 대조하고, 애니메이션·영상이 없어도 제출본의 핵심 정보가 전달되는지 확인한다.

그림이 슬라이드 끝까지 닿는 full-bleed와 의도한 겹침은 결함이 아니다. 장식 때문에 핵심 정보가 가려지거나, 의도하지 않은 위치에 잘리는지가 판단 기준이다.

`pptx_audit.py`는 XML·관계·기본 좌표를 검사하는 보조 도구다. 텍스트의 실제 줄넘침, 모든 그룹/회전 변환, 전체 폰트 상속, 사실성, 시각적 품질을 보증하지 않는다. 종료코드 0은 **실행한 자동 검사에서 오류를 발견하지 않았음**을 뜻한다.

## 7. 상태 보고와 전달

검증 상태를 `완료 / 실패 / 미실시 / 해당 없음`으로 구분하고 미실시를 통과로 바꾸지 않는다.

- 전달 형식과 편집 가능한 범위.
- 내용·수치 대조, 구조 검사, 폰트 확인, 실제 렌더 및 화면 검수의 상태.
- 글꼴 대체나 미확인 객체 등 남은 제한과 해당 장.
- 최종 PPTX, 필요한 PDF, 발표 노트, 근거 목록, 재생성에 필요한 소스·자산.

렌더러가 없으면 생성한 파일과 완료한 검사는 제공하되 화면 검수를 하지 못했다고 밝힌다. LibreOffice로 확인했다면 그 렌더러를 명시하고 사용자 환경 PowerPoint에서 확인한 것처럼 말하지 않는다. 제공된 자료만으로 사실을 확정할 수 없는 부분은 확인 필요 상태를 유지한다.

- [Microsoft PresentationML 구조](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document): 슬라이드·마스터·레이아웃·테마·관계.

API는 실제 설치 버전과 공식 문서를 대조한다. 위 자료의 기능 설명을 특정 실행 환경에서 이미 검증된 사실로 간주하지 않는다.
