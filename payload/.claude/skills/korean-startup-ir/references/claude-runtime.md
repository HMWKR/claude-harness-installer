# Claude 실행 지침

기본 대상은 Claude 웹·데스크톱의 사용자 Skill이다. Claude Code나 API에서 사용할 때는 실제 제공 기능의 차이를 확인하라. 특정 모델명이나 고정 내부 스킬 경로를 요구하지 않는다.

## 1. 스킬을 읽은 뒤 실제 환경을 확인하라

- 현재 읽은 SKILL.md의 절대 경로에서 스킬 루트를 확인하라. references와 scripts는 그 폴더 기준이다. 현재 작업 디렉터리가 스킬 폴더라고 가정하지 마라.
- 첨부 파일 위치와 쓸 수 있는 작업·출력 폴더를 현재 환경 안내에서 확인하라. 스킬 설치 폴더는 읽기용으로 사용하고 회사 자료·PPT·검사 결과는 작업 폴더에 작성하라.
- IR_SKILL_DIR, IR_PROJECT_DIR는 확인한 위치로 직접 정하는 작업용 변수다. Claude가 미리 제공하는 환경변수가 아니다. 경로에 공백이 있으면 인수를 따옴표로 감싸라.
- 현재 세션에 노출된 파일 읽기, 코드 실행, 이미지 열람, 파일 생성·출력 기능만 사용하라. 도구 이름과 API를 추측하지 마라.

## 2. Claude의 문서 제작 기능과 함께 사용하라

Claude 웹은 코드 실행과 파일 생성 기능이 켜져 있으면 관련 요청에 내장 PowerPoint 생성 기능을 사용할 수 있다. 이 패키지는 그 내장 구현을 포함하거나 대체하지 않는다.

1. 현재 사용 가능한 스킬·도구 안내에 PowerPoint/PPTX 제작 지침이 있으면 실제 경로를 읽고 해당 환경의 제작·렌더·전달 방법을 따르라.
2. 한국 IR의 사실, 목적, 장별 주장, 발표문, 공고 대응은 본 패키지의 지침을 적용하라. 제작 기능의 예시 내용이나 기본 팀·고객·수치를 회사 사실로 사용하지 마라.
3. 내장 제작 기능이 노출되지 않으면 사용 가능한 PptxGenJS 또는 python-pptx를 확인하라. 신규 생성과 기존 파일 가져오기·편집·보존 능력은 구별하라.
4. 두 제작 경로 모두 없으면 요청된 내용·설계·대본을 가능한 범위까지 완성하고 PPTX 미생성 상태와 필요한 다음 단계를 설명하라. HTML이나 PDF를 PPTX라고 부르지 마라.

내장 스킬의 안정적인 절대 경로는 이 패키지가 가정하지 않는다. 다른 제품의 전용 런타임, 커넥터, 개인 스킬 저장소에 접근하려 하지 마라.

## 3. Python 검사와 설치 범위를 구별하라

- ir_audit.py와 pptx_audit.py의 실제 검사는 Python 표준 라이브러리만 사용한다. 검사를 위해 python-pptx·PyMuPDF·PptxGenJS를 설치할 필요는 없다.
- preflight는 현재 Python·PATH·Node 환경에서 선택적 제작/변환 도구를 조사한다. 검사에서 미발견된 도구가 Claude 전체에 없다는 뜻은 아니다. 내장 제작 기능은 별도로 확인하라.
- 프로젝트별 node_modules를 찾도록 preflight는 확인한 IR_PROJECT_DIR에서 실행하되, 검사 스크립트는 IR_SKILL_DIR의 절대 경로로 호출하라.
- Claude 웹·Code의 패키지 설치 가능성은 현재 권한과 네트워크에 따라 확인하라. 가능하면 이미 제공된 도구를 먼저 사용하고 필요한 경우에만 작업 범위 안에서 설치하라. 전역 설정을 임의로 바꾸지 마라.
- API Skills 환경은 런타임 패키지 설치를 지원하지 않는다는 공식 안내가 있으므로 미리 설치된 의존성 안에서 작업하라. 웹과 API의 설정·도구를 혼용하지 마라.
- API를 사용하는 경우에는 호출 측이 필요한 Skill과 코드 실행 도구를 구성해야 한다. ZIP 업로드만으로 API 키·도구가 생성됐다고 가정하지 마라.

## 4. 긴 작업과 후속 수정

- 전체 덱을 만들 때 brief, 주장, 요구사항, 장별 내용과 시간을 ir-plan.json에 일찍 기록하고 수정에 맞춰 갱신하라.
- 후속 요청에서는 최신 입력과 기존 PPT·소스·원장을 읽고 영향받는 부분을 수정하라. 대화가 길어졌다고 모든 사실을 재생성하지 마라.
- 중간에 실제 파일을 생성했으면 그 경로와 완료·미실시 상태를 작업 기록에 남겨라. 존재하지 않는 파일을 완성했다고 말하지 마라.
- 독립 에이전트, 이미지 열람, 특정 렌더러의 사용 가능성을 가정하지 마라. 사용할 수 없는 검수는 미실시로 보고하라.

## 5. 출처·표현·전달

- 외부 출처는 실제 열람한 문서의 제목·기관·URL·발행/관측기간·확인 위치를 기록하라. 다른 플랫폼의 인용 토큰을 생성하지 마라.
- 슬라이드에는 읽을 수 있는 짧은 출처, 노트나 부록에는 전체 URL과 조건을 남겨라. 내부 원장 ID를 청중 화면에 노출하지 마라.
- 최종 파일 출력은 현재 Claude 안내에 맞춰 수행하라. 파일의 존재와 이름을 확인하고 사용자에게 실제 다운로드 가능한 결과를 제공하라. 출력 폴더 경로를 추측하지 마라.
- 렌더할 수 없더라도 실제로 만든 파일과 완료한 검사는 전달하고 남은 확인을 명확히 적어라. 사용자가 본문만 원하면 불필요한 파일 묶음을 만들지 마라.

## 공식 문서

확인일: 2026-10-28. 제품 UI·기능은 바뀔 수 있으므로 사용자의 현재 환경 안내를 우선한다.

- [Use skills in Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude): 코드 실행·파일 생성과 내장 PowerPoint 기능, 사용자 Skill 활성화.
- [How to create custom skills](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills): 이름과 폴더 일치, ZIP 포장, 웹 description 200자 안내, 의존성 차이.
- [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview): 필요할 때 지침·참조·스크립트를 읽는 구조와 실행 환경.
- [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices): 간결한 지침, 참조 분리, 실제 작업 검증.
- [Claude Code skills](https://code.claude.com/docs/en/skills): Code의 로컬 경로·호출·동기화는 현재 공식 안내에 따라 확인.

웹 업로드는 이름과 같은 단일 최상위 폴더 안에 대문자 SKILL.md를 둔다. 이 패키지의 description은 웹 안내의 더 짧은 200자 기준을 충족한다. 내장 문서 Skill의 코드·지침은 이 ZIP에 재배포하지 않는다.
