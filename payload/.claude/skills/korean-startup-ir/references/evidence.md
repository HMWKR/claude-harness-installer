# IR 주장·시장·실증의 근거 검수

목차: 주장 유형 → 출처 연결 → 고객 증거 → 시장과 SOM → 숫자·비용 → 초안과 완료.

## 1. 주장 유형과 확인 상태를 구별하라

핵심 사업 주장과 숫자를 아래 유형으로 분류하라. 유형을 신뢰도 순위나 사업 성공 점수로 사용하지 마라.

| 유형 | 뜻 | 장표와 검수에서 할 일 |
|---|---|---|
| `fact` | 확인한 원자료나 관측으로 그 범위 안에서 뒷받침되는 사실 | 대상·기간·조건을 보존하고 확인 범위를 넘겨 일반화하지 말 것 |
| `reported` | 사용자·고객·기관의 보고는 있으나 뒷받침 자료까지 확인하지 않은 내용 | 보고 주체와 시점, 확인 한계를 표시할 것 |
| `derived` | 다른 값과 계산식에서 얻은 결과 | 입력값의 유형·출처와 계산식·단위를 추적하고 재계산할 것 |
| `forecast` | 특정 가정과 기간에 대한 전망 | 실적과 분리하고 가정·기간·민감도를 표시할 것 |
| `hypothesis` | 아직 시험하지 않았거나 결론이 나지 않은 설명·가격·수요 등의 가설 | 검증 계획과 필요한 증거를 연결할 것 |
| `missing` | 주장하거나 계산하는 데 필요한 자료가 없음 | 빈칸·자료 필요로 남기거나 해당 주장을 제거할 것 |

목표·일정·예정 기능은 현재 사실로 표현하지 말고 계획임을 표시하라.
설명용 가상 인물·사례·수치는 실제 회사 증거와 분리하고 예시라는 표시를 유지하라.
근거의 확인 상태는 원문 확인, 간접 보고만 확인, 미확인, 자료 간 상충으로 따로 판단하라.
원문을 읽은 사실, 계산을 맞춘 사실, 고객 가설이 검증된 사실을 혼동하지 마라.
`reported`를 무조건 삭제할 필요는 없지만 독립 검증된 실적처럼 바꾸지 마라.

## 2. 주장과 원자료를 왕복할 수 있게 하라

핵심 주장마다 다음을 내부 근거 기록에 남기라. 내용 검토 자체는 특정 형식에 종속시키지 말고, 전체 덱을 제작하거나 자동 검사할 때는 `contracts.md`의 `ir-plan.json` 형식을 사용하라.

- 주장 내용과 사용 장표, 주장 유형, 확인 상태.
- 자료 소유자·작성기관·제목과 URL 또는 실제 파일 위치.
- 문서 페이지·절·표, 스프레드시트 시트·셀, 로그의 기간·조회 조건 등 원문 위치.
- 발행일·자료 기준기간·열람일을 구별한 날짜.
- 대상·표본 수·분모·중복 제거 기준·측정 조건.
- 단위·통화·부가세·집계 범위와 계산식.
- 확인하지 못한 부분, 상충 자료, 적용 한계.

회사 고객·매출·유지율·제품 성능은 회사의 거래·사용·시험 자료로 뒷받침하라.
외부 산업 통계나 경쟁사 실적을 우리 회사의 검증 결과로 바꾸지 마라.
회사가 제공한 요약 숫자만 있으면 제공 주체를 표시하고 원자료 검토 여부를 별도로 적으라.
파일에 숫자가 있다는 이유만으로 의미·집계 기준까지 확인했다고 하지 마라.
외부 자료는 원 작성기관의 표·보고서·공시·제품 문서를 우선하라.
검색 요약만으로 핵심 숫자를 확정하지 말고 원문을 열어 범위와 주석을 읽으라.
접근할 수 없는 자료는 접근한 것처럼 인용하지 말고 실제 확인한 범위만 남기라.
서로 다른 수치가 나오면 더 유리한 값만 선택하지 말고 정의·기간·표본의 차이를 확인하라.
장표에는 이해에 필요한 짧은 출처·기준일을, 상세 기록에는 직접 찾을 수 있는 원문 위치를 남기라.
내부 검수 ID와 작업 상태를 발표 화면의 사용자 흐름에 노출하지 마라.

## 3. 고객 증거가 입증하는 질문을 한정하라

| 확보한 자료 | 그 자료로 설명할 수 있는 범위 | 자동으로 확장하면 안 되는 주장 |
|---|---|---|
| 인터뷰·설문 | 해당 표본의 문제·현재 행동·응답 | 전체 시장 수요·구매 실적 |
| 무료 사용·테스트 | 특정 조건에서 사용한 사실과 관측 결과 | 유료 고객·매출 |
| 긍정적 후기 | 응답자가 보고한 경험 | 실측하지 않은 절감률·제품 성능 |
| 지불 의향 | 응답 시점과 조건의 의향 | 결제 전환·실제 구매 |
| LOI·MOU | 문서에 기재된 의사·협력 범위·조건 | 확정 주문·매출·구매 보장 |
| PoC | 정해진 범위의 실증 수행과 관측 결과 | 상용 도입·PMF·반복 매출 |
| 유료 PoC | 확인된 실증 대가와 시험 결과 | 일반 상품의 반복 구매 |
| 계약·발주 | 확인된 약정 범위·기간·조건 | 전액 입금·전액 매출 인식 |
| 결제·재구매 | 확인된 지급과 반복 거래 | 모든 고객의 유지·PMF 확정 |

유료/무료, 예정/진행/완료, 계약/입금/매출, 신규/누적/현재 유효를 각각 구별하라.
LOI·MOU의 구속력이나 구매 의무를 제목만 보고 판단하지 말고 문서의 실제 조건을 확인하라.
같은 기업의 여러 담당자·계정·시험 회차를 고객사 수에 중복 집계하지 마라.
성공률은 성공 건수와 전체 시도 수, 제외 기준, 기간을 함께 확인하라.
선택한 성공 사례만으로 평균 성능·일반 고객 성과를 주장하지 마라.
유료 증거가 없어도 실제로 관측한 문제·사용 반응·다음 검증 계획을 정리하며 제작을 계속하라.

## 4. 과금 단위에서 시장과 SOM을 계산하라

먼저 누가 무엇을 기준으로 비용을 지급하는지 정의하라: 사람·팀·기업·사업장·프로젝트·거래 등.
통계의 기업체·사업체·법인·지점·종사자 수가 실제 과금 단위와 맞는지 확인하라.
등록 대상 전체를 활동 고객이나 도입 가능한 고객으로 간주하지 마라.
시장 금액과 고객 수, 총거래액과 매출을 같은 경제량인 것처럼 비교하지 마라.

1. 고객·지역·제품 범위와 기간, 금액 또는 수량 기준을 정하라.
2. 해당 범위의 대상 수와 통계 정의·주석·기준연도를 확인하라.
3. 실제 제공 가능한 업종·규모·언어·도입 조건을 적용하라.
4. 가격·구매 빈도·과금 방식의 근거와 가정을 구별하라.
5. 도달 채널·영업 주기·전환·제공 역량·유지 가정을 연결해 확보 가능 범위를 계산하라.
6. 핵심 가정이 달라질 때 결과가 얼마나 달라지는지 보여 주라.

SOM을 임의의 시장 점유율 하나로 정하지 마라.
도달 가능한 고객 → 평가·도입 검토 가능한 고객 → 전환 → 제공 역량 → 유지·재구매를 근거에 맞춰 연결하라.
관측 전환율이 없으면 가정으로 남기고 확정 고객 수로 표현하지 마라.
복수 채널의 고객·시장 범위가 겹치면 중복을 제거하라.
같은 기간·시장 정의·경제량을 사용했을 때만 TAM·SAM·SOM의 포함 관계를 비교하라.
상위 산업의 매출을 우리 제품의 구매 가능 지출로 그대로 가져오지 마라.
연말 고객 수 × 연간 단가를 그해 실제 매출로 단정하지 말고 고객 유입·결제·제공 시점을 반영하라.
공식 통계의 한계로 직접 계산이 불가능하면 확인된 범위와 미확인 변수를 제시하라.

## 5. 단위·기간·원가를 같은 기준으로 맞추라

금액은 계산 원장에서 정밀도를 유지하고 표시 단계에서만 반올림하라.
원·만원·백만원·억원을 표·차트 안에서 무표시로 섞지 마라.
월·분기·연간, 당기간·누적·기말·평균, 실제값·전망값을 분리하라.
비교 공시는 사업연도, 보고서 종류, 연결/별도, 당분기/누적 기준을 맞추라.
부가세 포함/제외, 총거래액/수수료 매출, 일회성/반복 매출을 표시하라.
외화는 원통화 금액, 환율 방향, 적용값, 기준일 또는 평균 기간, 출처를 기록하라.
환율을 확인할 수 없으면 변환값을 임의로 확정하지 말고 원통화와 가정을 보존하라.
성장률은 기준값·비교기간을 확인하고 기준값이 0이면 일반적인 증가율 식을 사용하지 마라.
시장자료 발행 연도와 실제 통계 기준연도를 구별하라.

비용·시간 절감 비교는 동일한 과업 범위와 완료 품질을 기준으로 하라.
제작물 길이·해상도·분량, 작업자 개입, 시도 횟수, 검수·수정 범위를 필요한 만큼 명시하라.
실측 자료에는 관측일, 표본, 조건, 성공·실패·재시도, 평균 또는 중앙값의 선택을 남기라.
API 요금·도구 구독·인건비·외주·운영 비용 중 포함·제외한 범위를 표시하라.
한 번의 성공 호출 비용을 완성 산출물의 총원가로 제시하지 마라.
현재 가격표로 계산한 견적과 실제 지출, 고객의 지불가격을 구별하라.
실측하지 않은 개선치는 목표·가정으로 표시하고 실적 그래프에 섞지 마라.

## 6. 부족한 근거를 처리하며 계속 진행하라

미확인 사실 때문에 전체 작업을 중단하지 말고 확인된 부분의 서사·장표·대본·디자인을 완성하라.
누락 사실은 자료 필요 표시, 범위를 좁힌 표현, 주장 제거 중 적절한 방식으로 처리하라.
외부 조사로 해결할 수 있는 시장·경쟁 정보와 회사만 확인할 수 있는 실적을 구별하라.
핵심 주장에 필요한 자료가 남아 있으면 결과물을 초안으로 제공하고 필요한 자료와 위치를 짧게 알리라.
표현을 낮추거나 주장을 제거해 미확인 사실이 최종본에 남지 않게 했다면 그 범위에서 완료를 판단하라.
원문·숫자·주장이 바뀌면 영향을 받는 계산·장표·대본·부록과 검수 상태를 갱신하라.
검수 기록만 복사하여 변경된 산출물을 확인한 것처럼 표시하지 마라.

공식 조사 진입점과 적용 범위는 [korean-context.md](korean-context.md)의 출처 표를 참고하라.
