## 3. 추가 절차 (체크리스트 — 건너뛰지 않는다)

1. **출처**: 저장소 별·라이선스·최근 커밋·아카이브 여부(`gh api repos/<r>`). 무라이선스는 보류.
2. **내용 점검**: SKILL.md·references·**scripts 전부** 나열(`find`로 파일 수 확인 — API 목록의 크기 0 폴더를 "빈 폴더"로 오판하지 않는다). 네트워크·실행(`fetch`·`curl`·`child_process`·`eval`), 쓰기 호출, 비밀 접근, 자체 브라우저(Puppeteer·Playwright·Lighthouse) 지시를 스캔.
3. **설치**: 전역(`--global --copy` 또는 공식 플러그인). 제3자 훅은 기본 끔 — Stop 훅은 fablize 단일 권위와 충돌.
4. **역할 배치**: 라우터 ①방향 ②크래프트 ③게이트 ④눈 중 한 칸에 넣고, 겹치는 스킬과의 경계를 한 줄로 적는다. 브라우저를 쓰는 기능은 aside로 치환.
5. **실검증**: 실제 호출 1회(스킬 발동·CLI 실행·MCP 도구 호출) 결과를 확인한 뒤에만 1번 표로 옮긴다. 이 파일을 갱신한다.

## 4. 디자인 QA 스크립트 (aside 전용, 실측 검증됨 — codex 교차검수 1차 22건·2차 10건·3차 5건 + 2026-09-30 감사 반영)

```bash
~/.claude/skills/design-toolchain/scripts/run-qa.sh <URL> <출력폴더> [태그]
# 종료코드 0 = 네 조합 완전 검사 + axe 위반 0 + 수동 확인 항목 0 · 1 = 불완전(누락·건너뜀·시간 초과·검산 실패 — 통과 아님)
#         2 = 완전 검사에서 axe 위반 · 3 = 위반 0이지만 자동 판정 불가 항목 있음(axe 보류·테마 전환 미확인 등 — 목록 확인 후에만 통과)
```
- 구성: `capture.js`(구간 캡처) · `measure.js`(Vitals·axe) · `theme.js`(테마 강제 공용 함수, 두 스크립트에 인라인) · `stitch.py`(이어 붙이기·검산) · `render.py`(자리표시자 치환 단일 정본 — clone-site capture-contract §8도 사용). 의존성: Aside 앱, ImageMagick `magick`(없으면 사전 점검에서 rc=1).
- aside repl 1회는 120초 제한이라 **조합·모드마다 따로 부른다**(캡처 4회, Vitals 1회, axe 4회). 캡처 한 조합은 95초 예산·구간 60개 상한을 넘으면 중단하고 META를 남긴다.
- 375·1280 × 다크·라이트 **전체 페이지**: 같은 출처 iframe 구간 캡처(직전 구간이 실제로 찍힌 위치 바로 다음으로 스크롤) → 실제 스크롤 위치로 겹침 제거(구간별 실제 배율) → 이어 붙임 → 높이 = fullH × 배율(구간 수 픽셀 이내) 검산. 구간 PNG의 가로·세로 배율이 다르거나 구간끼리 배율이 다르면 불완전.
- 테마는 시스템과 무관하게 강제: `prefers-color-scheme` 조건만 참/거짓으로 치환하고 다른 조건(min-width 등)은 보존, `@import`·`@supports`·`@layer`·중첩 `@media`까지 재귀. 시트 자체의 media(`<link media>`·`<style media>`, 교차 출처 시트 포함)·`<picture><source media>`·`color-scheme: light dark`(`light-dark()`·meta 포함)도 강제한다(계산 스타일·PNG로 4조합 검증). `not`·`or` 조건은 처리 못 하고 rc=3으로 보고, 교차 출처 시트 **안쪽** 규칙은 읽지 못해 개수만 보고한다. 클래스·data-theme 방식 테마는 강제하지 못한다 — 테마 강제 지점이 0이거나 다크·라이트 결과 이미지가 같으면 "테마 전환 미확인"(rc=3)으로 알린다(단일 테마 사이트면 정상).
- 캡처 안정화: 부드러운 스크롤 끔, 구간마다 보이는 이미지 로드(최대 2초)·유한 애니메이션·전환 완료(최대 1.5초) 대기 — 스크롤 등장 효과가 도중 상태로 찍히지 않게, 시간 안에 못 끝난 개수는 rc=3으로 보고. **직전 구간에 완전히 찍힌 fixed·sticky만 이후 구간에서 숨김**(맨 위 헤더·중간 sticky 모두 제자리 1회, 화면 90% 이상을 덮는 fixed 배경·grain 레이어는 모든 구간에 유지), 하단 도달 후 높이·이미지 안정화 대기(지연 로딩 포함, 무한 스크롤은 재측정 10회 상한 — 정확히 10회 늘고 멈춘 페이지는 완전), 문서가 줄어 스크롤이 당겨지면 실제 위치로 기록, 스크롤바 숨김.
- 실패 처리(모두 **불완전 rc=1**): 탭 창이 조합 크기(1280×800·375×812)보다 작으면 `VIEWPORT_TOO_SMALL`(창을 키워 다시 실행), iframe 로드 15초·axe 로드 15초·axe 실행 30초 제한, `X-Frame-Options`·`frame-ancestors` 차단은 `FRAME_BLOCKED`, axe 탭이 브라우저 오류 페이지면 `PAGE_LOAD_ERROR`, 촬영 중단(구간 기록 없음)·하단 지연 로딩 미안정·예산(`BUDGET`)·구간 상한(`SEGMENT_CAP`)·스크롤 막힘(`NO_SCROLL_PROGRESS`)·이미 찍은 구간보다 문서가 짧아짐(`SHRANK`)·**내부 스크롤 컨테이너**(앱 셸 — 화면 절반 이상 크기의 요소가 스크롤하면 그 안은 찍히지 않음). 탭 정리는 finally. `@import`에 붙은 테마 조건과 한 조건 안의 중복 테마 조건도 변환한다. "찍힘" 표시는 스크린샷 성공 뒤에만 한다. 실행마다 같은 태그의 옛 `full-*-<태그>.png`를 먼저 지운다(건너뛴 조합의 옛 화면이 남지 않게). 실패 시 오류 줄은 구간 base64를 빼고 300자로 잘라 보인다.
- 측정: 페이지 안 Web Vitals(LCP, CLS 세션 윈도우, FCP, TTFB — 새 항목이 1.5초 멈출 때까지 관찰, 6초 한계면 provisional) + axe-core 4.13.0 WCAG 2.2 AA(창 폭·375 × 다크·라이트). axe는 사용자 실세션 탭에 주입되므로 **SRI(sha384) 고정**(npm 레지스트리 무결성과 대조한 사본 기준 — 버전을 올리면 measure.js의 `AXE_SRI`도 함께 바꾼다, 불일치면 `AXE_LOAD_ERROR`). axe "보류"(incomplete — 배경 그림·그라디언트 위 대비 등)는 종류·노드 수를 출력하고 rc=3(손으로 확인).
- 입력 방어: URL은 http/https만, 따옴표·공백·역슬래시 거부. 자리표시자(URL·조합·테마 함수)는 **한 번에** 치환해 넣은 값을 다시 훑지 않는다(URL은 JSON 문자열). 사전 점검 curl은 `-g`(URL의 `[]{}` 글로빙 끔)·`--proto =http,https`. 태그는 영숫자·`-`·`_`.
- 결과 PNG는 반드시 직접 열어 본다 — 수치만으로 시각 판정하지 않는다.
- 알려진 한계(실측): `page.screenshot({fullPage:true})`는 iframe 방식에서 첫 화면을 반복한 가짜 이미지를 만든다(쓰지 않음). Vitals는 사용자 창 크기에서만 잰다. INP는 상호작용이 필요해 재지 않는다. localhost 수치는 현장보다 낙관적이다. axe는 페이지에 있던 `window.axe`를 쓰지 않고 SRI 고정 엔진을 주입해 처음 대입된 진짜 객체를 재정의 불가 덫으로 잡아 실행한다(접근자·고정 속성으로 심어 둔 axe는 `AXE_SHADOWED_BY_PAGE`로 불완전) — 위협 모델은 우연한 전역 충돌·실수이며, 엔진 내부까지 고치는 적대적 페이지는 범위 밖. 2026-10-02 최종 검토로 확인한 한계: 처음 등장한 구간에서 화면 하단 fixed 요소가 가린 내용은 다시 찍히지 않는다. shadow DOM·adoptedStyleSheets 안의 테마 규칙과 로드 뒤 추가된 스타일은 강제하지 못한다. 바깥 탭에 뒤늦게 붙는 fixed 위젯은 모든 구간에 겹칠 수 있다. JS 타이머로 늦게 시작하는 등장 효과는 대기 대상에 안 잡힐 수 있다. 대상이 로드되지 않아 탭이 브라우저 오류 페이지가 되면 Aside `closeTab`이 실패해 탭이 남을 수 있다(2026-10-01 실측 — 사람이 닫는다). 결과는 `measure-<태그>.txt` 텍스트이고 clone-site 검증기의 `qa/metrics/*.json` 형식은 내지 않는다.

## 5. 영상 — Remotion 운용 근거와 한계 (2026-09-30 실측)

- **Remotion vs motiscope(2026-10-16 실측·사용자 지시)**: 방향이 반대인 도구다 — Remotion은 코드→영상, motiscope는 영상→측정값. 결과가 영상 파일이면 Remotion 위주, 참고 녹화를 웹 모션으로 옮기면 motiscope 위주, 정교함이 필요하면 둘을 이어 쓴다(Remotion이 후보를 렌더해 원본 녹화와 프레임 대조). 정본 `references/remotion-vs-motiscope.md`, 라우터 `rec2web` 초점 줄.

권유 기준과 운용 규칙 본문은 라우터 영상 블록(`scripts/uiux-skill-router.sh`, 영상 신호 때 주입)이 정본이다. 이 절은 그 규칙의 근거와 한계만 둔다.

- **스킬 구조**: `remotion-best-practices`가 라우터이며 안쪽 사본(`remotion-best-practices/remotion-*/REFERENCE.md`)을 불러온다. 2026-10-15 갱신(4.0.535)부터는 최상위 11종도 같은 업스트림 커밋이고, 안쪽 사본과의 차이는 문서 간 링크 표기뿐이다(diff로 확인). 이전(4.0.530 때)에는 최상위 `remotion-create·maps·markup·saas`가 4.0.529 사본이었다. 진입은 계속 라우터로 한다. 공식 Claude Code 플러그인(`remotion@remotion`)은 같은 스킬 묶음이라 중복 설치하지 않는다.
- **e2e 실측**: 스크래치 `remotion-e2e`(create-video --blank)에서 tsc 통과 → `render --frames=0,15,45,89 --image-format=png` 4장(첫 실행 33초 — 이때 Chrome Headless Shell을 `node_modules/.remotion/`에 내려받음) → PNG를 직접 확인(한글 글리프 정상, 타이밍 설계와 일치) → MP4 3.000초·1280×720·30fps·90프레임(`npx remotion ffprobe`) → Studio를 aside로 열어 타임라인·Inspector 확인.
- **픽셀 포맷**: create-video 기본값(`Config.setVideoImageFormat("jpeg")`)은 `yuvj420p`·color_range=pc(풀레인지)를 낸다. `Config.setVideoImageFormat("png")` + `Config.setPixelFormat("yuv420p")`(또는 CLI `--image-format=png --pixel-format=yuv420p`)로 표준 `yuv420p`가 나온다(설정·CLI 둘 다 실측, <project> 세션도 같은 결과).
- **ffmpeg**: 시스템 Homebrew ffmpeg/ffprobe 8.1_1은 `libx265.216.dylib` 누락으로 실행되지 않는다(dyld 오류 실측). 대신 Remotion 내장 `npx remotion ffmpeg|ffprobe`를 쓴다(내장 ffmpeg는 `--disable-filters` + 화이트리스트 필터 42종 빌드 — 2026-10-02 `-buildconf` 실측). 시스템 쪽 복구(`brew reinstall ffmpeg` 등)는 사용자 판단이며 실행하지 않았다. **갱신(2026-10-15)**: `brew upgrade`로 시스템 ffmpeg/ffprobe가 9.0.2가 되면서 `ffmpeg -version`이 정상 실행된다(8.1_1의 libx265 dyld 오류 해소 — main 실측, 같은 날 `ffprobe -version`도 9.0.2 확인). yt-dlp 2026.08.19를 새로 설치했다(watch 플러그인 의존). **갱신 2(2026-10-15)**: 실행된다고 필요한 필터가 다 있는 것은 아니다 — 9.0.2 기본 빌드에 libass·freetype이 없어 `drawtext`·`subtitles`·`vidstabdetect`·`vidstabtransform` 필터가 없다(ffmpeg-skill `doctor` "NOT ok" 실측, §1 행). 영상 속 글자·자막은 Remotion이 맡고, `ffmpeg-full`(GPL·keg-only·PATH 변경)은 설치하지 않았다 — 필요해지면 별도 승인 항목이다.
- **Studio**: 옵션 없는 `npx remotion studio`는 시스템 기본 브라우저를 연다(스킬 문서의 "in-app browser가 없으면" 분기) → `--no-open` + `open -b at.studio.AsideBrowser "<URL>"`. Studio 서버는 `*:<port>`로 LAN에도 열린다(lsof 실측). 공식 CLI 문서의 네트워크 옵션은 `--ipv4`뿐이고 호스트 제한 옵션은 찾지 못했다 → 확인이 끝나면 종료한다.
- **렌더 엔진과 브라우저 규칙**: 렌더는 Chrome Headless Shell로 로컬 번들을 프레임으로 굽는 작업이라 rigor §1의 예외로 둔다. 웹 페이지 탐색·검증은 여전히 aside만 쓴다.
- **렌더 방식 비교(2026-10-02 공식 문서, 결정: CLI 렌더 기본 — 사용자 확인)**: ① CLI 렌더(`npx remotion render`, Chrome Headless Shell) — 실제 Chrome 스크린샷이라 CSS 전부 그대로, FFmpeg 인코딩(코덱·pix_fmt 제어), 텔레메트리는 라이선스 키를 설정했을 때만, 이 하네스에서 프레임·MP4 실측. ② 브라우저 안 렌더(`@remotion/web-renderer`, 4.0.491부터 정식, Studio의 "Render in browser" — Aside 안에서 가능) — CSS를 캔버스에 흉내 내는 방식이라 `perspective`·`transform-style`(3D)·`writing-mode`(한글 세로쓰기)·이미지 `background-image`·`object-position` 미지원(HTML-in-canvas 모드 예외), WebCodecs 인코딩, **라이선스 키와 무관하게 렌더마다 텔레메트리 전송**, 결과가 브라우저 다운로드로 떨어진다. ③ Lambda·Vercel 클라우드 렌더 — 계정·비용·소재 업로드가 필요해 이 용도엔 과함. Remotion 5.0에서 "Automators"(프로그램 렌더) 유형은 licenseKey·텔레메트리가 의무가 될 예정 — 그때 라이선스 유형을 다시 확인한다.
- **설치 부작용**: npm 11의 allow-scripts 정책이 esbuild postinstall을 건너뛰지만 렌더는 정상이다(스캐폴드가 rspack 사용). 전역 CLI는 프로젝트 밖 용도이고, 프로젝트 안에서는 `npx remotion`을 쓴다(1번 표 Remotion 행).
- **라이선스**: remotion-dev/remotion `LICENSE.md` 원문 기준으로 무료 대상은 개인, 직원 3명 이하 영리 조직, 비영리, 평가 목적이다. 그 밖의 영리 조직은 Company License(remotion.pro)가 필요하다. create-video도 "free for teams of up to 3"를 출력한다. Remotion 5.0에서 조건이 약간 바뀔 예정이다(LICENSE.md 머리말).
- **도구 경계**: 생성형 영상 클립은 fal.ai image-to-video + Blender 기준 프레임(2026-10-22 사용자 지시), 사진·일러스트는 codex 이미지, 웹 UI 모션은 영상이 아니므로 UI 라우팅이 맡는다. 인터랙티브 시안은 Claude Design 아티팩트(영상 내보내기 없음), 스토리보드·앰비언트 루프는 Figma 모션 `export_video`(<project> 실측, 파일 권한에 따라 다름).
- **2026-10-15 GitHub 조사(후보 19개)**: 코드형 엔진은 Remotion과 HyperFrames 둘이 실질적 선택지다. Revideo(puppeteer 렌더, postinstall 텔레메트리)·Motion Canvas(npm 마지막 배포 2025-02)는 에이전트 스킬이 없다. 보완 도구는 ffmpeg-skill(후처리·납품 검사 — §1 행)만 설치했다.
