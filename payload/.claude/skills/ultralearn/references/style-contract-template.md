# 스타일 계약서 템플릿 (초안 에이전트 전원 필독·엄수)

> 사용법: `<...>` 자리를 대상 프로젝트에 맞게 채워 스크래치에 `style-contract.md`로 저장하고,
> 모든 초안·검수 에이전트 브리프에 "필독 1순위"로 지정한다.

## 0. 출력 형식 — <포맷: py-percent / 스크립트 / html>

- (노트북 계열이면) 파일은 `# %% [markdown]`(마크다운 셀)과 `# %%`(코드 셀) 마커로 셀을 나눈다.
  마크다운 셀의 모든 줄은 `# ` 접두, 빈 줄은 `#` 단독. 파일 첫 셀은 반드시 제목 마크다운 셀.
- 매직/특수 명령(<%pip, %sql 등>)은 **셀의 첫 줄**에만 — 앞에 주석 금지, 설명은 직전 마크다운 셀로.

## 1. 언어·톤

- 전부 한국어. 입문자(<전제 지식 수준>) 기준.
- 마크다운 셀: 개념 → 왜 필요한가 → 지금부터 뭘 할 건가. 비유 1개 이상 권장.
- 코드 주석: "무엇을"이 아니라 **"왜, 이 값이 어디서 와서 어디로 가는지, 지금 시스템에서 무슨 일이 벌어지는지"**. 분량 제한 없음 — 코드보다 주석이 길어도 된다.
- 금지: 영어 설명문, 근거 없는 단정("항상/반드시 ~합니다"), 존재하지 않는 API 창작.

## 2. 필수 구성 요소 (유닛마다)

1. **제목 셀**: `## <ID>. <제목>` + 배우는 것 3줄 요약 + 선행 유닛 링크.
2. **[🖱️ 노코드 UI로 하기]**: 같은 작업의 화면 절차 단계별 서술. 코드와 결과가 같음을 명시.
3. **[👀 조회 실험]** ≥1: 중간 산물을 직접 열어보는 코드 + "무엇이 보여야 하는지".
4. **[💥 일부러 틀려보기]** ≥1: `# ⚠️ 이 셀은 일부러 에러를 냅니다` 주석 + 에러 원문 해석 셀.
   실행이 위험하면 읽기 전용 시나리오(에러 원문 인용)로 대체. 에러 없는 침묵 실패도 인정하되
   "무엇이 조용히 잘못되는지" 관찰 셀 필수.
5. **[🔁 <대안 방식>로도 해보기]**: 주 도구(<예: Spark 코드>)로 한 핵심 작업을 보조 도구(<예: SQL>)로
   재수행 + 언제 무엇이 낫나 한 줄. 대응물이 없으면 "왜 안 되는가" 설명 박스로 대체 가능.
6. **✅ 체크포인트** 마지막 셀: "이 출력이 나오면 성공" 목록 + 다음 유닛 예고
   (예고문은 다음 유닛의 실제 내용과 일치해야 한다 — 검수 대상).

## 3. 코드 규칙

- **주 도구 우선**: <예: 조회·변환·저장은 PySpark 체인, SQL은 [🔁]와 SQL 전용 문법에만>.
- 환경값은 상단 "환경 상수" 셀에 대문자 변수로. 사용자마다 다른 값에 `# 🔧 내 환경에 맞게 수정`.
  파생 가능한 이름(테이블 등)은 리터럴 금지 — f-string으로 상수에서 파생.
- API 호출은 **api-patterns.md 등재분만**. 없는 API가 필요하면 코드 대신
  "📚 공식 문서 확인" 박스 + URL.
- 시크릿·키: 실습용 평문 허용 시에도 `# ⚠️ 실습용 — 마지막에 <보관소>로 이관` 주석 필수.

## 4. 분량

- 유닛당 셀 15~35개, 마크다운:코드 ≈ 1:1.
- 원본 코드를 재사용하되 주석을 계약 기준으로 전면 증강하고 주 도구 우선으로 재구성.
- 원본의 오타·버그는 고치지 말고 "🔍 오류 찾기" 교육 포인트로 다룬다.

## 5. 저장 위치

- `<프로젝트>/notebooks_src/<ID>_<이름>.<확장자>` — 파일명은 브리프 지정값 그대로.

## 6. 예외 조항

- [🔁] 대체 허용: 대응물이 없는 작업은 "왜 안 되는가" 박스로 대체.
- [💥] 침묵 실패 허용: 관찰 셀이 있으면 에러 없는 실패도 인정.
