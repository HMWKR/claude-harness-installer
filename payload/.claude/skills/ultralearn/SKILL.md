# Ultralearn — 코드를 체감형 학습 키트로

## Overview

받은 코드를 **심층 분석 → 앵커 문서 → 병렬 초안 → 적대 검수 → 실측 검증**의 5단 공정으로, 입문자가 손으로 따라하며 "왜 이렇게 하는지"를 체감하는 학습 키트(분석 문서 + 실습 유닛 + HTML 가이드)로 변환한다.

핵심 원리: **설명하지 말고 실험시킨다.** 모든 개념은 [👀 조회]·[💥 일부러 틀려보기] 실험으로 체감시키고, 모든 완료는 ✅ 체크포인트("이 출력이 나오면 성공")로 판정한다.

## 산출물 계약 (4종)

```
<프로젝트>/
├── analysis/심층분석-*.md   # 전체 흐름 지도(mermaid) + 파일별 "왜" 해부 + 숨은 버그 발굴
├── notebooks/(또는 labs/)   # 실습 유닛 — 환경에 맞는 포맷 (아래 표)
├── guide/*.html             # 브라우저에 띄워 옆에 두는 따라가기 지도 (자체완결 CSS, 라이트/다크)
└── (검증 증거는 스크래치에)  # 실호출 로그·렌더 스크린샷·구조 검증 출력
```

| 실행 환경 | 실습 유닛 포맷 |
|---|---|
| Databricks/Jupyter | py-percent 소스 → `scripts/py2ipynb.py`로 .ipynb 변환 |
| CLI/라이브러리 | 단계별 실행 스크립트 + 실행 로그 주석 |
| 웹 프론트 | 단계별 html/js + 브라우저 확인 절차 |

## 공정 (5단)

1. **심층 분석**: 대상 파일 전부 정독 → 데이터/제어 흐름 지도 → 파일별 {개념/내부 동작/왜 이렇게 설계/학습자 과제와의 연결}. **원본의 오타·버그·잔재는 고치지 말고 "🔍 오류 찾기" 교육 포인트로 승격**한다.
2. **앵커 문서 3종 작성** (초안 에이전트 전원의 필독서 — 환각 차단 장치):
   - `style-contract.md`: [references/style-contract-template.md](references/style-contract-template.md)를 대상에 맞게 조정
   - `env-constants.md`: 원본에서 추출한 환경값 + **원본 파일 간 불일치 목록**(그대로 반복 금지)
   - `api-patterns.md`: 허용 API 패턴만 등재, 신뢰 표기 필수 — `[실호출검증]`(이 세션에서 직접 호출 성공) / `[원본검증]`(원본 코드에 존재) / `[문서기반]`(적대 검수 대상). **패턴집에 없는 API는 코드 금지, "📚 공식 문서 확인" 박스로.**
3. **실측 먼저**: 외부 API·순수 로직은 초안 작성 **전에** 로컬에서 실호출/실행해 실제 응답을 확보한다. 실측 데이터가 곧 교재의 예시가 된다.
4. **병렬 초안 → 적대 검수**: Workflow로 유닛별 초안 에이전트 병렬 실행(브리프 = 앵커 3종 + 유닛별 개요) → `critic` 에이전트 3~4명이 도메인 분담(API 시그니처/외부 API/교차참조·상수 일관성/스타일 계약)으로 결함을 찾는다. **발견 전량을 수정하고 강등하지 않는다.**
5. **검증 후 완료**: 변환(구조 검증) + HTML은 Playwright 실렌더 관찰(grounding) + 수정 반영을 grep으로 개별 확인. 실행 환경이 없어 못 돌리는 부분은 ✅ 체크포인트로 학습자에게 위임하고 **정직 보고에 명시**한다.

## Quick Reference — 유닛 필수 구성 6종

| 표기 | 의미 |
|---|---|
| 🖱️ 노코드 UI로 하기 | 같은 작업의 화면 클릭 절차 — "UI는 같은 API의 다른 입구"임을 보여줌 |
| 👀 조회 실험 | 중간 산물(변수·객체·테이블 내부)을 직접 열어보기 ≥1 |
| 💥 일부러 틀려보기 | 의도된 실패 + 에러 원문 해석 ≥1 (위험하면 읽기 전용 시나리오) |
| 🔁 대안 방식 | 주 도구로 한 작업을 보조 도구로 재수행 (없으면 "왜 안 되는가" 박스) |
| ✅ 체크포인트 | "이 출력이 나오면 성공" — 다음 유닛 진입 조건 |
| 🔧 환경 수정 표시 | 사용자마다 다른 값. 파생 가능한 이름은 f-string으로 상수에서 파생 |

주석 원칙: "무엇을"이 아니라 **"왜, 이 값이 어디서 와서 어디로 가는지"**. 분량 제한 없음.

## Common Mistakes (실측된 결함 카테고리)

| 실수 | 방지책 |
|---|---|
| API 시그니처 창작 (존재하지 않는 파라미터) | api-patterns 등재분만 사용, 나머지는 📚 박스 |
| 유닛 간 교차참조 오기 ("B2에서 만든 테이블"인데 실제는 B1) | critic에 교차참조 검수 도메인 배정 + 완성 후 grep |
| 환경값 하드코딩으로 상수 파라미터화 붕괴 | 파생명은 f-string, 리터럴엔 🔧 필수 |
| 예고문과 실물 불일치 ("다음 유닛에서 X를 그대로" 후 딴 것 사용) | 인접 유닛 첫·끝 셀을 짝으로 검수 |
| 매직 명령(%pip 등) 앞에 주석 → 셀 깨짐 | 매직은 셀 첫 줄, 설명은 직전 마크다운 셀 |
| 검증 없이 "실측" 표기 | 실호출 로그가 있는 것만 [실호출검증] |

## 완료 기준

goal(가능하면 fablize goals.py)에 잠금: ① 산출물 4종 존재 ② 구조 검증 통과 로그 ③ HTML 렌더 스크린샷 ④ 실호출 증거. 마무리 보고는 한 일/안 한 일/가정/미검증을 구분한다.
