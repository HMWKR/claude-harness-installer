# 판정단과 페르소나 — 점수를 실행 모델 밖에서 만든다

수치가 있는 기준은 측정으로 판정한다. 판정단은 수치가 없는 차원에만 쓴다: 위계, 타이포·색의 인상, 이미지, 문구, 신뢰, 모바일, 차별성, 경쟁 우위. 근거는 LLM 판정 연구다. 위치 편향(순서에 따라 결과가 바뀜), 자기 선호(자기 출력을 높게 봄), 장황함 편향이 실증돼 있다. 완화책은 순서 교환, 다른 계열 판정자, 앵커 루브릭, 근소 차 무승부다.

## 1. 구성(잠긴 엄격도대로)

| 엄격도 | 절대 점수 | 맞비교 | 페르소나 | 최종 검증 |
|---|---|---|---|---|
| 가볍게 | Claude 1 | — | — | Claude 검증자 1 |
| 표준 | Claude 3 + 다른 벤더 1(판정자마다 제시 순서를 무작위로 다르게) | — | 3명 | Claude 검증자 + 다른 벤더 |
| 표준(동종) | Claude 3 — 다른 벤더 판정석이 없는 환경 | — | 3명 | 관점이 다른 Claude 검증자 2 |
| 엄격 | Claude 5 + 다른 벤더 1 | 우리 대 경쟁사마다, 축마다 좌우 바꿔 두 번 | 3명 | 2인 보고서(`rigor.final_ok`) |

- 판정자는 회차마다 새로 띄운다. 이전 회차 점수나 대화를 가진 판정자는 쓰지 않는다. LLM의 UI 피드백은 회차가 거듭될수록 유용성이 떨어진다는 연구가 있다.
- Claude 판정자는 쓰기 도구가 없는 유형(이 하네스는 critic)으로 띄운다. 판정 JSON은 응답으로 돌려받고, 메인이 원문 그대로 파일로 저장한다. 고친 사람(메인 세션)은 점수를 매기지 않는다.
- 다른 벤더(이 하네스는 codex)는 메인이 직접 부른다. 그림을 보게 하려면 `codex exec -s read-only -C <자극 폴더> -i A.png -i B.png … "<프롬프트>"`를 쓴다. MCP 경로가 그림을 받지 못하면 그 판정석은 쓰지 않는다(모든 축을 채점해야 받는다).

## 2. 자극(보여 줄 것)과 봉인

1. 우리 페이지와 비교 대상의 대응 페이지를 **같은 폭**으로 준비한다(최소 1280·375). 경쟁사는 리서치 날짜의 캡처를 고정해 쓴다(경쟁사 사이트가 바뀌어 기준선이 흔들리지 않게). 우리 화면만 회차마다 새로 찍는다. 긴 전체 페이지는 입력에서 축소되어 디테일이 사라지므로 첫 화면과 절별 크롭으로 나눈다.
2. 모든 그림을 같은 형식으로 다시 저장하고 메타데이터를 지운다(예: `sips -s format png`, `magick … -strip`). 파일 머리(JPEG 지문 등)로 출처가 드러난 적이 있다.
3. 로고·회사 이름이 보이면 가린다. 가릴 수 없으면 그 판정을 "비블라인드"로 기록한다. 언어도 단서다. 우리만 한국어이고 경쟁사가 모두 영어면 판정자가 언어로 우리를 알아본다. 경쟁사의 같은 언어 페이지를 쓰고, 없으면 "비블라인드 위험: 언어"로 기록해 보고한다.
4. 라벨(A, B, C…)을 무작위로 붙이고, 판정자마다 순서를 바꾼다. 대응표(`{"A": "comp:acme", "B": "ours", "C": "ref:studio-x"}`)는 저장소 밖 파일에 쓰고 판정자에게 주지 않는다. 경쟁사(`comp:`)는 잠긴 비교 목록과 정확히 같아야 한다(빼거나 겹쳐 넣으면 거부). 기준점 레퍼런스(`ref:`)는 점수의 상한을 잡는 앵커로만 보여 주고 경쟁 지표에는 넣지 않는다.
5. 자극은 저장소 **밖** 임시 폴더에 복사하고 판정자는 그 폴더만 본다. 대응표 파일은 자극 폴더와 다른 곳에 둔다. 저장소 경로·작업 폴더 이름·회사 정보가 프롬프트에 들어가지 않게 한다.
6. 판정자를 띄우기 **전에** `D seal --dir W --round N --key <대응표 파일>`로 봉인한다. dloop가 대응표에 무작위 nonce를 넣고, 해시와 시각을 `rounds/rN/panel/seal.json`에 남긴다. 판정이 끝나면 대응표를 `rounds/rN/panel/key.json`으로 복사한다. panel은 key.json이 봉인과 다르거나, 판정 파일이 봉인보다 먼저 만들어졌으면 거부한다(exit 3). 점수를 본 뒤 어느 자극이 우리인지 고르지 못하게 하려는 것이다.

## 3. 판정자 프롬프트(절대 점수)

```
당신은 독립 디자인 심사위원이다. 아래 웹사이트 화면들(A, B, C …)을 같은 기준으로 채점한다.
어느 회사의 사이트인지, 누가 의뢰했는지 추측하지 말고 화면에 보이는 것만 본다. 양보다 질을 본다.
장식·절이 많다고 점수를 올리지 않는다.

먼저 blind_check를 쓴다: 알아본 회사 이름(없으면 빈 배열)과, 의뢰한 쪽으로 짐작되는 라벨(모르면 "unknown").

모든 화면의 모든 축에 1~5점과 근거(어느 화면의 어느 부분)를 쓴다. 빈칸이나 근거 없는 점수가 있으면 판정 전체를 다시 받는다.
- 5 = 이 분야 최고 수준 사이트와 견줄 만함(드물다) · 4 = 완성도 높고 결함이 눈에 띄지 않음
- 3 = 쓸 만하지만 평범하거나 결함이 보임 · 2 = 결함이 사용을 방해함 · 1 = 기본이 무너짐
축: hierarchy(위계·레이아웃·여백) · typography_color(타이포·색) · imagery(이미지·그래픽) · copy(문구 명확성)
    · trust(신뢰 장치) · mobile(375 화면) · distinctiveness(차별성·기억에 남음)

JSON만 출력:
{"judge":"<id>","vendor":"<anthropic|openai|…>","blind_check":{"recognized":[],"guessed_owner":"unknown"},
 "scores":{"A":{"hierarchy":4,…},…},"rationale":{"A":{"hierarchy":"첫 화면 제목과 행동 버튼의 대비…",…},…}}
```

결과를 `rounds/rN/panel/judge-<id>.json`으로 저장한다. 순서를 바꿔 다시 받으면 `judge-<id>@a.json`·`judge-<id>@b.json`으로 둔다(변형은 두 개까지). 그다음 `D panel`을 실행한다. 집계 규칙:
- 봉인한 모든 자극·축의 점수(1~5)와 근거가 있어야 받는다. 하나라도 빠지면 panel이 거부한다. 그 판정자에게서 다시 받는다.
- 판정자 단위로 먼저 평균한 뒤(순서 변형) 판정자 사이 중앙값을 낸다. 변형을 늘려도 한 표다. 판정자 수가 정족수(가볍게 1·표준 3·표준(동종) 3·엄격 5)에 못 미치면 점수 지표가 나오지 않는다.
- vendor는 계열로 묶는다(anthropic·openai·google…). "Claude Opus"도 anthropic이다. 모르는 이름은 다른 벤더로 치지 않는다.
- 축에서 우리가 이긴 것으로 세려면 중앙값 차이가 0.5 이상이고 판정자 과반이 같은 방향이어야 한다. 경쟁사 중앙값이 0.5 이상 높으면 진 것이다. 나머지는 무승부다.
- 판정자 절반 이상이 회사를 알아봤거나(recognized) 우리 라벨을 맞혔으면(guessed_owner) 점수 지표를 만들지 않는다(`panel.blind_breaches`는 남는다). 자극을 다시 가려 새 판정자로 재판정하고, 보고에 "비블라인드"를 적는다.

## 4. 맞비교(엄격)

같은 쌍을 두 번, 서로 다른 호출로 묻는다. 한 번은 우리를 왼쪽, 한 번은 오른쪽에 둔다. 한 응답 안에서 두 순서를 다 보여 주면 순서 교환이 아니다.

```
두 화면 L, R을 비교한다. 축마다 더 나은 쪽(L, R, tie)과 근거를 쓴다. 차이가 근소하면 tie다.
JSON만: {"judge":"<id>","pairs":[{"left":"B","right":"A","axis":"hierarchy","winner":"B","why":"…"},…]}
```

라벨은 대응표의 라벨을 그대로 쓴다. winner는 left·right 라벨이나 tie만 쓰고, why(근거)가 없으면 거부된다. 판정자 하나의 두 방향 결과는 `rounds/rN/panel/pairs-<id>.json` 한 파일에 합친다(같은 판정자가 여러 파일에 있으면 거부). 축마다 두 방향을 다 낸 판정자가 3명 이상이어야 한다. `D panel`의 집계:
- 판정자 하나: 두 방향 모두 이긴 경우만 승, 두 방향 모두 진 경우만 패, 나머지는 무승부다.
- 판정자들 사이: 진 표가 없고 과반이 승이면 승, 진 표가 이긴 표 이상이면 패, 나머지는 무승부다(낮은 등급 보존).

## 5. 페르소나 — 실제로 써 보는 사람

회차마다 세 명이 우리 사이트를 직접 써 본다. 경쟁사와 비교해 어디서 막히는지, 무엇이 부족한지 본다. 이 하네스는 Aside 에이전트 레인(`aside "<작업>"`)을 쓴다. 증거가 아니라 결함 후보다. 사용량 한도가 있으니 질문을 묶어서 적게 부른다.

| 페르소나 | 보는 것 |
|---|---|
| 결정권자(기업 담당자·구매자) | 3초 안에 무엇을 하는 곳인지, 믿을 만한지, 다음 행동(가입·문의·요청)이 분명한지 |
| 실사용자(지원자·회원) | 가입·입력 흐름, 오류·빈 상태, 모바일에서의 사용 |
| 시니어 디자이너 | 시각 위계·타이포·색·여백·모션·호버·전환·마이크로 인터랙션·일관성·완성도. 요청에 없는 것까지 열린 범위로 |

페르소나마다 답 원문을 `rounds/rN/personas/<이름>.md`로 저장한다. 이 실행 기록이 있어야 페르소나 수로 센다. 이 회차 실행에서 나온 지적을 한 줄에 하나씩 `findings.jsonl`에 쓴다(지적이 없으면 빈 파일).

```json
{"id":"p-r1-03","persona":"designer","severity":"High","where":"/ 375 첫 화면","summary":"행동 버튼이 접힘 아래로 밀림"}
```

severity는 High·Medium·Low로 쓰거나 NN/g 숫자를 그대로 쓴다: 4·3 → High, 2 → Medium, 1 → Low, 0은 세지 않는다. critical·blocker·major는 High, minor는 Medium, cosmetic은 Low로 읽고, 그 밖의 표기는 거부된다. status는 쓰지 않는다. 이 회차의 지적은 모두 열린 것으로 세고, 고쳤는지는 다음 회차의 새 페르소나 실행에서 사라졌는지로 확인한다. 다음으로 `D personas`를 실행한다.

## 6. 천장과 무승부

- 5점을 흔하게 주면 1위와 동점이 되어 비교가 무너진다. 루브릭의 5점은 "분야 최고 수준"으로 앵커를 고정한다. 비교 대상에 강한 레퍼런스를 하나 넣는다.
- 동점은 동점이다. 근소 차를 승으로 해석해 등급을 올리지 않는다.
- AI 판정을 사람 대상 실험이나 업계 전체에서의 우위로 표현하지 않는다. "블라인드 AI 판정단 기준"이라고 쓴다.
