# 리서치 게이트 — 경쟁사·레퍼런스 확보

비교할 대상이 없으면 "경쟁사 수준"이라는 기준이 성립하지 않는다. 그래서 기준선 측정 전에 이 게이트를 통과한다. 리서치가 이미 있으면 재사용하고 부족한 것만 채운다. 없으면 처음부터 한다.

## 1. 기존 리서치 판정

`D init`이 `state.json.research`에 후보 폴더·파일을 적는다. 탐지 이름은 web-crawling·research·competitors·benchmark·경쟁사·레퍼런스다. 다른 이름을 쓰는 프로젝트도 있으니 프로젝트 지침과 작업 기록도 훑는다.

충분한지는 아래 넷으로 본다. 하나라도 빠지면 그 부분만 보강한다. 0바이트 캡처, 사이트마다 본문이 똑같은 템플릿 메모, 측정 없는 메모는 없는 것으로 친다(`state.json` research의 `empty_files`를 본다). 수집일은 폴더 이름의 날짜로 본다(복사하면 수정 시각이 바뀐다).

| 항목 | 충분 |
|---|---|
| 대상 수 | 사용자가 고른 리서치 범위(5곳 / 10~15곳 / 지정 목록)를 채움 |
| 같은 폭 캡처 | 잠긴 측정 폭(`criteria.lock.json.targets.widths`) 중 최소 375·1280 캡처가 있음 |
| 같은 페이지 | 우리 대상 범위와 대응하는 페이지가 있음(홈↔홈, 가입·문의 흐름↔흐름) |
| 시점 | 90일 이내. 더 오래됐으면 다시 캡처(사이트는 자주 바뀐다) |

## 2. 대상 찾기 — 없을 때

0. **Refero 먼저**(2026-10-16 사용자 결제·지시): `refero_search_sites`·`refero_search_styles`로 같은 분야·느낌의 실제 제품 사이트를 찾고, `refero_get_style`·`refero_search_screens`(우리 대상 페이지와 대응하는 화면)·`refero_search_flows`(가입·문의 흐름)로 근거를 모은다. Refero에 있는 대상은 스타일 UUID·화면 UUID를 비교 목록에 남기고, 같은 폭 캡처·DOM이 더 필요한 곳만 아래 크롤로 보강한다.
1. 프로젝트 문서(README·PRODUCT.md·사업 설명·명세)에서 분야·고객·지역을 뽑는다.
2. 웹 검색으로 후보를 모은다.
   - 직접 경쟁: "<분야> 회사", "<제품> alternatives", 리뷰·비교 사이트(B2B는 G2·Capterra·Clutch 류), 해당 지역 검색 결과
   - 인접: 같은 고객에게 다른 방식으로 파는 서비스
   - 디자인 레퍼런스: 같은 분야의 수상작·큐레이션 갤러리(Awwwards·One Page Love·Godly 류)
3. 고른다. 기본 배분은 이렇다.
   - 5곳: 직접 3 + 레퍼런스 2
   - 10~15곳: 직접 5~7 + 인접 2~4 + 레퍼런스 3~4
   - 고른 이유와 뺀 후보, 뺀 이유를 남긴다. 판정 비교(`comp:`)에는 **직접 경쟁만** 넣는다. 레퍼런스는 방향 참고용이고, 판정단에 보여 줄 때는 점수 앵커(`ref:`)로만 쓴다.
4. 사용자가 목록을 지정했으면 그 목록이 우선이다. 찾은 후보는 "추가 제안"으로만 보고한다.

## 3. 수집 — 사이트마다

공개 페이지만 수집하고 robots.txt를 지킨다. 가입·로그인·제출·결제는 하지 않는다. 쿠키 동의 버튼도 누르지 않는다(가려지면 그 요소만 숨기고 숨겼다고 적는다).

| 수집물 | 방법 | 저장 |
|---|---|---|
| 캡처 | 잠긴 폭(최소 375·1280)으로, 홈 + 대응 페이지 | `web-crawling/<site>/<YYYY-MM-DD>/<page>@<w>.png` |
| 측정 | 같은 페이지에 page-audit.js 실행 — 우리와 같은 지표로 비교 | `…/<page>@<w>.audit.json` |
| 구조 | 제목 개요, 절 순서와 절 유형, 주 행동 버튼 이름·위치, 내비게이션 | `notes.md` |
| 문구 | 첫 화면 제목·부제·버튼 문구, 신뢰 장치(과정 설명·정책·연락처·검증 방식) | `notes.md` |
| 시각 | 서체(계산값)·크기 단계·색(상위 사용색)·이미지 유형·여백 리듬 | `notes.md` + audit의 samples |
| 모션 | 진입·스크롤·호버·전환 효과 목록, 감속 대응 여부 | `notes.md` |
| 흐름 | 가입·문의·요청 단계 수, 필드, 진행 표시, 저장 후 이어 하기 | `notes.md`(제출하지 않고 관찰만) |

이 하네스에서는 `aside repl`로 크롤하고, 폭별 캡처는 run-qa.sh 또는 같은 출처 iframe을 쓴다. 원시 출력에 세션 토큰·추적 ID가 섞이면 프로젝트 폴더가 아니라 임시 폴더에 둔다.

## 4. 종합과 적대 검수

`W/research/synthesis.md`에 네 가지를 쓴다.

- 차원별 공통 패턴과 예외. 사이트 이름과 근거 파일 경로를 붙인다.
- 우리 판단을 세 칸으로 나눈다: **반드시 가질 것 / 가져올 것 / 가져오지 않을 것**. 가져오지 않는 이유에는 금지 규칙·사업 사실·사용자 지시가 포함된다.
- 확인하지 못한 것. 로그인 뒤 화면, 동적으로만 보이는 상태 등이다.
- 적대 검수 정정표. 쓰기 도구 없는 검수자가 수치·인용·추정 표기를 반박한 내용을 받아 반영한다.

## 5. 비교 대상 잠금

`W/research/comparison-set.json`을 쓴다.

```json
{
  "date": "YYYY-MM-DD",
  "competitors": [
    {"name": "acme", "url": "https://acme.example", "category": "direct",
     "why": "같은 고객·같은 서비스", "pages": {"home": "https://acme.example/", "signup": "https://acme.example/join"}}
  ],
  "references": [{"name": "studio-x", "url": "https://…", "why": "같은 분야 수상작"}]
}
```

기준선(r0) 판정을 봉인(`D seal`)하기 전에 `D lockset --dir W`를 실행한다. 잠근 판의 해시는 `locks/chain.jsonl`에 남고, check는 지금 목록이 마지막 판과 같은지 매번 대조한다. 봉인 전이면 목록을 고쳐 다시 잠글 수 있지만, 봉인·판정한 회차가 생기면 lockset이 거부한다. 그 뒤에 바꿔야 하면 사용자 승인을 받고, 이전 판정 회차를 무효로 기록한 뒤 새 작업 폴더에서 다시 시작한다. 직접 경쟁이 1곳뿐이면 경쟁 우위 판정이 한 곳에 좌우되므로 lockset이 알린다 — 리서치로 더 찾을 수 있으면 보탠다.

## 6. 수시 조사

회차 중에도 결정에 사실이 필요하면 조사한다. 추측으로 메우지 않는다.

| 필요 | 1순위 |
|---|---|
| 라이브러리·프레임워크 사용법 | 공식 문서(이 하네스는 context7) |
| 표준 수치(WCAG·Core Web Vitals 등) | 1차 출처(W3C·web.dev) |
| 경쟁사 세부 화면·문구 | 크롤 |
| 글꼴·이미지 라이선스 | 배포처 라이선스 원문 |
| 사업 사실(법인·고객·파트너) | 조사로 확정하지 않는다. 사용자에게 묻는다 |

출처와 확인 날짜는 `W/decision-log.md`에 남긴다.
